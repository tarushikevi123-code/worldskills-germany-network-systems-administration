01. DEVICE ROLE AND DESIGN SUMMARY
-----------------------------------
Weil_A2 is the secondary Layer 3 access switch in the Weilburg site. It provides
SVIs and default-gateway redundancy for the HR, Sales, Engineering and WLAN
VLANs. It connects to Weil_C1 through a routed Layer 3 EtherChannel (Port-channel3)
and connects to Weil_A1 through a Layer 2 trunk EtherChannel (Port-channel1).

Expected design roles from the competition task:
- Rapid PVST+ secondary root for VLANs 2, 4, 6 and 8.
- HSRP standby for VLANs 2 and 4.
- HSRP active for VLANs 6 and 8.
- OSPF process 1, router ID 2.2.2.2, in Area 0 for Weilburg interfaces.
- DHCP relay toward 10.10.130.2 on the client VLAN SVIs.
- Access-port Port Security, including a 50-MAC limit on the WLAN/AP port.

04. HSRP BEHAVIOR AND PACKET TRACER TRACKING ADAPTATION
-------------------------------------------------------
HSRP group IDs match the VLAN IDs. The virtual IP addresses are the last usable
addresses in the corresponding client VLAN subnets.

Observed configuration on Weil_A2:
- VLAN 2: group 2, VIP 10.10.2.30, no explicit priority command (IOS default).
- VLAN 4: group 4, VIP 10.10.4.14, no explicit priority command (IOS default).
- VLAN 6: group 6, VIP 10.10.6.62, priority 115.
- VLAN 8: group 8, VIP 10.10.8.6, priority 115.
- Preemption is enabled on all four groups.
- Both physical routed EtherChannel member interfaces are tracked on all four groups:
  GigabitEthernet1/0/23 and GigabitEthernet1/0/24.
- No explicit decrement value is present in the captured commands. Confirm the
  effective decrement using `show standby` / `show standby detail` on the device.

Packet Tracer adaptation:
The project implementation uses per-member tracking because the Packet Tracer
version used did not accept the Port-channel interface as the HSRP tracking
object. Tracking both physical members is intended to lower HSRP priority when
both uplink members are lost, while allowing the surviving member of the LACP
bundle to continue forwarding when only one member fails.

For the intended HSRP distribution:
- Weil_A2 should be Standby for VLANs 2 and 4.
- Weil_A2 should be Active for VLANs 6 and 8.

Priority note:
The official task specifies preferred-active priority 105 and standby priority
100. The supplied running-config shows 115 on Weil_A2 VLANs 6 and 8; the absence
of an explicit priority on VLANs 2 and 4 means the platform default applies.
This is a documented implementation difference, not silently corrected here.

Tracking behavior note:
If the simulator applies the default decrement of 10 per tracked object, the
expected priority progression for an active VLAN 6/8 group is 115 with both
members up, 105 with one member down, and 95 with both members down. Confirm the
actual decrement and state transitions on the device before claiming failover
verification.
