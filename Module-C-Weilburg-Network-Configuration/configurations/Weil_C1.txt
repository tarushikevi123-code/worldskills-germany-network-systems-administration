01. DEVICE ROLE AND DESIGN SUMMARY
================================================================================

Weil_C1 is the central Layer 3 core switch in the Weilburg site. It connects
both Layer 3 access switches to the two WAN routers and provides the Layer 3
interface for the centralized server VLAN.

The captured configuration shows these roles and connections:

- Routed LACP EtherChannel Port-channel2 towards Weil_A1.
- Routed LACP EtherChannel Port-channel3 towards Weil_A2.
- Routed interface GigabitEthernet1/0/1 towards Weil_W1.
- Routed interface GigabitEthernet1/0/2 towards Weil_W2.
- Server VLAN 130 SVI with address 10.10.130.6/29.
- Server-facing access-port assignments on GigabitEthernet1/0/3 through
  GigabitEthernet1/0/20, with access VLAN 130 configured.
- OSPF process 1, router ID 3.3.3.3, with the Weilburg interfaces advertised
  in Area 0.
- SSH version 2 and local authentication for console and VTY access.
- Standard ACL 1 applied inbound to the VTY lines to restrict remote
  management to the server subnet.

Expected neighboring devices and transit addressing from the official task:

  Weil_A1  <-> Weil_C1 Port-channel2 : 10.11.1.2/30 <-> 10.11.1.1/30
  Weil_A2  <-> Weil_C1 Port-channel3 : 10.11.2.2/30 <-> 10.11.2.1/30
  Weil_C1  <-> Weil_W1              : 10.11.3.1/30 <-> 10.11.3.2/30
  Weil_C1  <-> Weil_W2              : 10.11.4.1/30 <-> 10.11.4.2/30

Server network:

  VLAN 130 network : 10.10.130.0/29
  Weil_C1 SVI      : 10.10.130.6/29
  DHCP server      : 10.10.130.2
  DNS server       : 10.10.130.3

The DHCP and DNS addresses are specified by the competition task. They are
not configured as local services on Weil_C1.

intended members bundled (P). Confirm the exact remote physical interfaces on

Access-port STP settings
------------------------

The server-facing ports Gi1/0/3 through Gi1/0/20 do not show the following
required interface-level settings in the captured running configuration:

  switchport mode access
  spanning-tree portfast
  spanning-tree bpduguard enable

ports must use PortFast and BPDU protection configured directly on the
interfaces. These commands should be checked against the final Packet Tracer
configuration before the project is described as fully compliant.

Do not apply PortFast or BPDU Guard to routed uplinks or EtherChannel members.

  enable secret <REDACTED>
  access-list 1 permit 10.10.130.0 0.0.0.7

Console line:

VTY lines 0–4 and 5–15:

  access-class 1 in
  login local
  transport input ssh

ACL 1 allows the server subnet 10.10.130.0/29 to initiate remote management
sessions to the switch. Because the ACL is applied inbound to the VTY lines,
other source addresses are denied by the implicit deny at the end of the
standard ACL.

The captured running configuration shows `ip ssh version 2`, but it does not
show the RSA key-generation command or prove that SSH is operational. Verify:

  show ip ssh
  show crypto key mypubkey rsa
  show line
  show access-lists 1

The original type 5 hashes have been intentionally excluded. Do not publish
passwords, password hashes, private keys or other credentials in this public
repository.

10. FINDINGS AND ITEMS REQUIRING VERIFICATION
================================================================================

The following findings are based strictly on the supplied Weil_C1 running-
configuration transcript and the official task requirements.

A. Items that match the intended design
---------------------------------------

1. Loopback1 is configured as 10.10.111.1/32, matching the task appendix.
2. OSPF process 1 uses router ID 3.3.3.3, matching the task.
3. The two routed access-switch links use the expected /30 addresses:
   - Port-channel2: 10.11.1.1/30 towards Weil_A1.
   - Port-channel3: 10.11.2.1/30 towards Weil_A2.
4. The routed WAN links use the expected local addresses:
   - Gi1/0/1: 10.11.3.1/30 towards Weil_W1.
   - Gi1/0/2: 10.11.4.1/30 towards Weil_W2.
5. VLAN 130 SVI is configured as 10.10.130.6/29, matching the task appendix.
6. The routed EtherChannel member interfaces use LACP active mode.
7. SSH version 2, local console/VTY authentication, VTY source ACL 1 and the
   MOTD banner are present in the captured configuration.
8. No Port Security configuration is shown on Weil_C1. This is consistent with
   the task requirement that Port Security be activated only on the access
   switches.

B. Configuration differences or possible compliance gaps
---------------------------------------------------------

1. Spanning Tree mode
   Captured: `spanning-tree mode pvst`
   Task: 802.1w / Rapid PVST+ on all switches.
   Action: verify Packet Tracer support and the intended final mode.

2. Server access-port mode
   Captured Gi1/0/3–Gi1/0/20: `switchport access vlan 130` only.
   Not shown: explicit `switchport mode access`.
   Task: end-device interfaces must be fixed access ports.
   Action: verify and, if supported/required, add explicit access mode.

3. Server access-port STP protection
   Captured Gi1/0/3–Gi1/0/20 do not show interface-level PortFast or BPDU Guard.
   Task: access ports must use PortFast and BPDU protection configured on the
   individual access interfaces.
   Action: verify and correct if those ports connect to end devices/servers.

4. VLAN database
   A separate `vlan 130` stanza is not shown in the supplied running-config.
   Action: confirm VLAN 130 is present and active using `show vlan brief`.

5. SSH key state
   SSH v2 is configured, but RSA key presence/SSH operational state is not
   established by this transcript.
   Action: check `show ip ssh` and `show crypto key mypubkey rsa`.

6. OSPF operation
   OSPF process and network statements are present, but no neighbor output or
   learned route table was supplied for Weil_C1.
   Action: collect `show ip ospf neighbor`, `show ip route ospf` and
   `show ip route 0.0.0.0`.

C. Not applicable / not present on this device in the supplied design
---------------------------------------------------------------------

- HSRP is configured on Weil_A1 and Weil_A2, not on Weil_C1.
- DHCP relay is not shown on Vlan130; the DHCP server is directly attached to
  this same server VLAN.
- NAT/PAT and the Intranet extended ACL are configured on the WAN routers,
  not on Weil_C1.

D. Overall status
-----------------

Weil_C1 has the expected core addressing, routed EtherChannels, WAN routed
interfaces, server SVI and OSPF process configuration. However, the supplied
running-config shows PVST rather than Rapid PVST+, and the server access ports
do not show explicit fixed-access mode, PortFast or BPDU Guard. Operational
EtherChannel, OSPF, VLAN and SSH state still requires live verification.

This record should therefore be treated as a sanitized configuration and
compliance review, not a declaration that every task requirement has passed.
